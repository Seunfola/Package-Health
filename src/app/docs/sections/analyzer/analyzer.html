Analyzing a private repository

DepVault never asks for a personal access token to reach a private repo. Instead it uses a GitHub App: you install/configure the app on the account or organization that owns the repo, GitHub hands DepVault a short-lived, narrowly-scoped installation token behind the scenes, and nothing longer-lived than that is ever stored.

  1. Sign in, then open the Analyze Private Repository form on the homepage.
  2. Click Connect GitHub App. You're redirected to GitHub to choose which account/organization and which repositories to grant access to — the same flow as installing any other GitHub App.
  3. GitHub redirects you back automatically once you confirm. The form now shows a dropdown of every installation you've connected.
  4. Pick the installation that owns the repo, paste the repo URL, and analyze.
Ownership is verified server-side. DepVault only ever uses an installation you've personally connected through this flow — it never accepts an arbitrary installation id from a request, even from a signed-in user.
If Connect GitHub App reports the app isn't configured, the DepVault deployment you're using hasn't set up its GitHub App yet — this is an operator-side setup step, not something fixable from the browser.
