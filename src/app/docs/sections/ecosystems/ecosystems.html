Package managers are not ecosystems. npm, yarn, pnpm and bun all resolve from the one npm registry and share package.json, so they are a single ecosystem to the scoring engine. What differs is the lockfile and the remediation command — DepVault detects the manager (Corepack's packageManager field first, then lockfiles including bun.lockb) and prints a command you can actually run, rather than assuming one tool.

Internal and workspace packages

A workspace:, file: or link: dependency is code you wrote. It has no registry entry, but it is not unverifiable: it inherits every advisory it pulls in. DepVault scores these from local source and marks them internal in every report — terminal, PR comment and dashboard — so you can tell at a glance which model produced a number before comparing it with the row above.

The marker is deliberately not colour alone: it carries a filled background, bold monospace weight and an uppercase label, so it survives a greyscale print, a colour-blind reader and a fast skim of a long table.

No source-level analysis. DepVault has no static-analysis engine, so an internal package's score reflects its dependency surface and maintenance health — not the risk of its own code. A hand-written crypto helper with no dependencies will score well; that is a statement about its supply chain, not about its implementation.

How scoring works

DepVault combines known vulnerability exposure, package criticality, maintainer diversity, freshness, maintenance, popularity, and license signals. Security contributes 45% of the Trust Score; license and maintenance 20% each; popularity 15%. Freshness adjusts maintenance, and Monte Carlo sampling can provide the displayed 95% confidence interval. The score helps compare choices; the finding list identifies urgent remediation work.
