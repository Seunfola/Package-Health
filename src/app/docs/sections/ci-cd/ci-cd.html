CI/CD Beyond GitHub

LeakGuard's CI story isn't GitHub-only. Every integration — the GitHub Action, GitLab, Bitbucket, Jenkins, or a CI system with none of those — relies on the identical exit-code contract, so a result never disagrees between platforms:

$ depvault leakguard scan <path> --fail-on <low|medium|high|critical>

Exit 0 when nothing at or above --fail-on severity survives allowlist/placeholder filtering; exit 1 otherwise. Add --sarif <file> for a SARIF 2.1.0 report any code-scanning UI can render. No integration re-derives this decision — each one renders what the CLI already decided.

GitLab CI

Copy this job into your project's .gitlab-ci.yml:

leakguard:
  stage: test
  image: node:20-alpine
  variables:
    LEAKGUARD_FAIL_ON: 'high'
    LEAKGUARD_CLI_VERSION: '1.1.0'  # pin deliberately, bump on purpose
  script:
    - npx -y "@deepvaultscan/cli@${LEAKGUARD_CLI_VERSION}" leakguard scan . --fail-on ${LEAKGUARD_FAIL_ON} --sarif leakguard-results.sarif
  artifacts:
    when: always
    paths: [leakguard-results.sarif]
    expire_in: 30 days
  rules:
    - if: $CI_PIPELINE_SOURCE == 'merge_request_event'
    - if: $CI_COMMIT_BRANCH == $CI_DEFAULT_BRANCH

Bitbucket Pipelines

Merge this step into bitbucket-pipelines.yml:

pipelines:
  pull-requests:
    '**':
      - step:
          name: LeakGuard secret scan
          script:
            - npx -y "@deepvaultscan/cli@1.1.0" leakguard scan . --fail-on high --sarif leakguard-results.sarif
          artifacts:
            - leakguard-results.sarif

Jenkins

Add this stage to a declarative Jenkinsfile:

stage('LeakGuard secret scan') {
    steps {
        sh '''
            npx -y "@deepvaultscan/cli@1.1.0" \
                leakguard scan . --fail-on high \
                --sarif leakguard-results.sarif
        '''
    }
    post {
        always {
            archiveArtifacts artifacts: 'leakguard-results.sarif', allowEmptyArchive: true
        }
    }
}
CLI version pin: these templates pin @deepvaultscan/cli@1.1.0 per this repository's own docs/leakguard/ templates. The CLI isn't published to npm yet (see Downloads & Install Links) — until it is, run these steps against a self-built binary instead of npx.
Opt-in network checks stay opt-in in CI too: append --verify-live or --blast-radius only once your org has explicitly decided CI may generate that traffic (a real auth-probe to the credential's own provider, or a GitHub code-search query) — neither flag is implied by running in CI.
