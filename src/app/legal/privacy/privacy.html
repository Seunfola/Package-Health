Privacy and Data Handling Policy

DepVault is built with a Zero-Trust, Zero-Code philosophy. We designed our architecture specifically so that enterprise users never have to worry about exposing intellectual property or proprietary source code.

1. What Data Do We Process?

  • NO Source Code: DepVault NEVER uploads, scans, or touches your proprietary .ts, .js, or .py files.
  • Dependency Lists Only: The local CLI parses your package.json (or equivalent) locally and only transmits the names and versions of open-source dependencies (e.g., express@4.18.2) to our backend.
  • Private Packages: If you have internal private packages (e.g., @mycompany/auth), the backend will return a 404. We immediately discard this query and do not log or store private package names.

2. Historical Trending Data

To provide the "Time Machine" 30-day Trust Score graph, we store anonymized snapshots securely.

  • Data Stored: Ecosystem (e.g., npm), Package Name, Trust Score, Timestamp.
  • Data NOT Stored: Who requested the scan, IP addresses, or internal project names.

3. VectorDB and AI Processing

DepVault scaffolds AI embeddings strictly for analyzing public vulnerability databases (e.g., DepVault HealthScan, NVD) and public package descriptions to detect malware/typosquatting heuristics. We do not train any Machine Learning or LLM models on your internal queries.

4. CI/CD Gatekeeper Security

The GitHub Actions workflow (depvault-gatekeeper.yml) runs entirely within your own CI/CD runner. The execution, evaluation, and blocking of Pull Requests happens completely on your infrastructure.
